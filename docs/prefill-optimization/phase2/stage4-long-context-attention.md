# Stage 4 — Long-context paged prefill attention

Execution order 8. Land four independently measured changes in order. Start from the current F16 direct and four-split routes. At execution time the dispatcher chooses four splits for rows in {512,1024,2048}, position ≥ 6144 and position + rows ≤ 8192 when scratch is bound. F32 already supports unsplit WMMA. Q8_0 uses the tiled reader. Reuse the [Phase 1 split-key fixtures and baseline](../phase1/acceptance/07-long-attention.md).

## 4a — F16 shared-memory layout

In [attention_wmma.hip](../../../kernels/hip/prefill/attention_wmma.hip) try a K/V leading dimension of `HD + 8` halves against `HD`, starting with HD=256. Use it in the producer's per-key destination, K/V fragment loads, second key tile in the seed scan, and base offsets of subsequent shared arrays. Keep query and probability strides as defined today. Calculate launch bytes from the same layout: ordinary/partial kernels need both 16-key tiles plus probabilities, the max-only kernel stages 32 keys without V/probabilities. Check alignment of vector stores, function attributes, shared size reported to the support predicate, and the 64 KiB limit for each variant. Scope the experiment to F16 so other formats supply controls.

**Accept** only with finite direct-vs-padded native results bitwise equal or max absolute < 1e-4, including the split path, and repeated unprofiled improvements both on isolated attention and on pp512/8192. Time the complete attention operation including seed and merge where applicable. Record VGPR/spills, dynamic LDS and `rocprofv3` LDS bank conflicts (target < 5% from the historical 44%). If timing fails, continue 4b from the prior layout.

## 4b — Extend F16 split dispatch by measured cell

1. Build an isolated forced-route probe with identical populated K/V pages for direct, 2, 4 and 8 splits. Use rows 512 and 2048 at each position 4096, 6144, 7680, 8192, 12288 and 14336. Include existing 1024-row controls, then repeat representative long positions with tails 64, 127, 511 and 513. Fix rows when measuring the 8K boundary. An 8256-token prompt ending in 64 new rows changes two variables.
2. Eight splits need explicit implementation even for a probe. The [flag encoding](../../../backend/hip/bridge/yuuka_hip.h), [validator/executor](../../../backend/hip/bridge/bridge.cpp), and four-entry weight array, broadcasts and accumulation loops in the merge currently handle at most four. Exercise eight through a benchmark-only launcher sized for eight and a merge specialization that consumes all eight records. If eight wins, add an additive forced-count encoding preserving existing flag values, reject unknown combinations, and carry the maximum eligible split count into checked scratch sizing on both sides before enabling that route. Keep four-split-only plans at their present reservation.
3. Calculate scratch in bytes as `rows * heads * (splits * (head_dim + 2) + 1) * sizeof(float)`. Partials contain max, sum and value accumulator, followed by one shared seed maximum per row/head. Extend [model scratch eligibility](../../../engine/gpu/model.go) and the [plan's query-row guard](../../../engine/gpu/plan.go) only for passing tail cells. Keep the position-dependent decision in the [native launcher](../../../kernels/hip/prefill/prefill.hip): Go caches plans by row count and reuses them at different absolute positions. Check effective end position, displacement of a cropped final query and capacity. A single cropped query keeps its existing route.
4. Hold the leading 512-key seed fixed for the first trial. Preserve causal clipping, empty partial semantics and exactly one sigmoid gate after the merge. Test noncontiguous page IDs, partial pages, uneven split ends and repeatability. At every newly enabled band compare at least two populated prompts (including near 8K and 16K), same F16 pages, token IDs and chunking, direct versus auto split. Require full-logit max absolute ≤ 0.30 for final prefill and three subsequent decode steps, same greedy tokens. Rerun the existing 8K window. The earlier 1024-key seed reached 0.373. An unverified seed change needs a separate comparison.
5. **Accept a cell** only if total seed + partial + merge improves in interleaved unprofiled trials and the corresponding whole prompt also wins with the numerical and scratch gates met. Publish the exact row/position ranges and bytes. Keep direct for losing cells and exercise both sides of each new dispatch edge.

## 4c — Unsplit WMMA reading a Q8_0 pool

Use the physical row from the block table and the byte stride from [kv.cuh](../../../kernels/hip/kv.cuh). Each 34-byte block stores an FP16 scale and 32 signed digits. Share the scale across its values, multiply in FP32, then convert to half when staging K/V. Keep addresses valid at two-byte block alignment. Zero masked key slots. KV writes and pool size remain in the existing packed format.

Add Q8_0 instantiations in the unsplit launcher for the head widths and gated/dense layouts actually verified. Update `attention_wmma_supported` and [PrefillAttentionMMA](../../../backend/hip/dispatch.go) together. Unsupported geometries retain the tiled path. In [native tests](../../../tests/hip/prefill_test.cpp), compare against a CPU attention oracle reading the **same packed bytes** and the forced tiled device reader. Require the existing native bound `abs(error) <= 5e-3 * (1 + abs(reference))`, repeatable outputs, permuted pages and a partial final tile. Verify short and long cases, and the [model KV-format regression](../../../engine/gpu/runtime_test.go) (Q8_0 vs F32 bound 0.5 and identical greedy sequence). For the new same-Q8_0 route comparison apply the attention gates 0.05 short and 0.30 long with matching greedy continuation.

**Accept** at ≥ 1850 tok/s for unprofiled pp8192 with Q8_0 and chunk 512 (historical tiled ~1077 tok/s). Compare at fixed chunk against the tiled control. Run a separate best-chunk series if desired. The matched-token driver is F16-only today. Use an explicit `--kv-type q8_0` HIP CLI and same-format model harness for these checks.

## 4d — F32 and Q8_0 split-key

Thread KV dtype from the model's allocation predicate through plan construction to the op descriptor and native switch. Preserve the old F16 [Go method](../../../backend/hip/hip.go) as a forwarding wrapper if adding a typed method. Keep native descriptor layout and existing F16 callers valid. Instantiate both max-only and partial variants per format. The present F32 staging branch disallows `KeyOnly`: make the max scan load K alone, including packed Q8_0, with a null V pointer. Reuse the same FP32 merge. Allocate scratch only for supported gated GQA geometry, feasible capacity and measured cells, independently by dtype.

Extend [plan validation](../../../tests/hip/plan_validation_test.cpp) with exact-fit and one-byte-short scratch and packed pools, alias, alignment, head geometry, dtype, incompatible flags and missing scratch on a forced split. Compare split to unsplit WMMA **within each format** on 8K and 16K at fixed chunk. Require max absolute logit delta ≤ 0.30, matching three greedy continuation steps, and repeatable unprofiled long-prompt improvements for each accepted format. Exercise the original F16 direct/split cases and forced tiled route. Keep an unsuccessful format on its verified unsplit policy.

For each slice record median/spread, row count, **start** position, dtype, split count, scratch bytes, compiler resources, and unprofiled prompt time in separate columns. Repeat process order on the same gfx1151 host and record the build and driver metadata per the [testing protocol](../../testing.md).
