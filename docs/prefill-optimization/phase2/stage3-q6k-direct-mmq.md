# Stage 3 — Direct int8 WMMA for Q6_K

Execution order 7. Target the 16 Q6_K FFN down matrices (9216 → 2560), then the five attention V matrices (2560 → 1024). The other Q6_K tensor in the reference GGUF serves the embedding/output path. The generic Q6_K MMQ already provides an int8 product oracle. The direct Q4_K/Q5_K path already handles masked token tiles from 128 rows onward. [MMQ kernel and dispatcher](../../../kernels/hip/gemm/mmq_gemm.hip) · [Shape evidence](roadmap.md)

## Iteration A — FFN down

1. Extend `stage_direct_weights` with a dtype-specialized Q6_K branch. For a 256-value superblock read 128 low bytes, 64 high bytes, 16 signed subblock scales and the FP16 superblock scale at offset 208. Reuse the `q6k_span8` decode order to recover signed digits in [-32,31]. Stage four 8-value spans per 32-value pair into the existing direct operand layout. Use 16-bit-safe global loads. Even an aligned first row has alternating block alignment owing to the 210-byte stride.
2. Use the two existing LDS scale slots for independent `d * sc[2j]` and `d * sc[2j+1]`. In the gfx1151 direct loop issue two signed int8 WMMA instructions with **separate zero int32 accumulators**. For each output accumulate the low 16 product times its scale and `xDS.x`, followed by the high 16 product times its scale and the same `xDS.x`. Follow the generic Q6_K FP32 accumulation order. Q6_K consumes neither the minimum term nor `xDS.y`. Preserve the Q4/Q5 paired accumulation branch.
3. Add only the FFN down shape to `measured_direct_shape` and the Q6_K launch switch. Select the runtime-shape direct specialization, preserve pointer alignment checks and existing masked/unmasked row selection. The fixed Q4_K 512-row specialization hardcodes a different row stride. Other shapes and short rows continue through the established dispatcher.
4. Both shapes already exist in `model_shapes`. Remove the Q6_K exclusion for these two cells in the [direct-only sweep](../../../bench/hip/prefill_sweep.cpp). Build the same sweep source against both libraries. Quantize once and time the multiply after warmup. Verify the instantiated kernel in a separate trace.

**Exit A.** Exercise full CPU products of packed Q6_K and the same Q8_1 digits/scales in the [native suite](../../../tests/hip/prefill_test.cpp). Vary scales between adjacent 16-value groups (including opposite signs), exercise multiple superblocks and both halves of each block. Require all outputs finite, max absolute error ≤ 2e-4 and untouched output guards for exact and partial tiles (128, 129, 192, 511, 512 rows). Use the [resource report](../../../scripts/kernel_resources.sh) to require zero VGPR spills and dynamic LDS ≤ 30 KiB. Compare the 512-row FFN down median independently against Generic MMQ. Target ≤ 1.15 ms, diagnostic, versus the roadmap's historical 1.57–1.68 ms.

## Iteration B — Attention V and product verification

Enable 2560 → 1024 only after repeating the tensor, alignment, masked-row and resource checks on that shape. Include an ineligible width/shape and sub-128 control to demonstrate generic/short dispatch. Compare the Q4_K and Q5_K controls from Stage 1a for collateral regressions. Keep the accepted FFN down route independently selectable if V fails.

On the verified gfx1151 host, run `build/yuuka_prefill_sweep --direct-mmq` for control and candidate, then Release CTest including `hip_prefill_correctness`. Independently run matched, unprofiled pp128/512/2048/8192 on identical IDs, F16 KV and chunk per arm. Interleave control/candidate/candidate/control, record medians and spread, then reverse process order. Require repeatable whole-prompt improvements at the four lengths and preserve existing greedy/logit gates. With identical digits, scales and accumulation order compare complete logits byte-for-byte and investigate any disagreement before enabling the route. Report nonaligned 129/511 as dispatch checks. Keep the microbenchmark and per-prompt tables separate. [Reproduction and paired inputs](acceptance/01-direct-rows.md#reproduction)

Estimated production change: 90–150 HIP lines in the MMQ translation unit. Budget two additional files for the CPU product fixtures and isolated sweep. Record accepted shapes and measurements in the kernel contract and Phase 2 acceptance.
