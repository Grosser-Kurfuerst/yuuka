# Stage 6 — Compact final-row matvec and residual normalization

Execution order 10. Measure 6a and 6b against separate controls. The roadmap permits pulling **only 6a** forward if Stage 2 leaves the paired pp128 +5% target about 1 ms away. Rebaseline 6b after the actual Stage 2 gate route has been selected. [Execution order](roadmap.md)

## 6a — Use the prepared Q8_1 row in the five cropped projections

The [prefill planner](../../../engine/gpu/plan.go) chooses cropping only for the final full-attention layer with `prefillLastLogit`. It writes **all** K/V before `MarkTail`, moves the last residual to row zero and evaluates the remaining query/output and FFN for one row. Its route choice still uses the **parent** row count. Thus a parent selecting MMQ can launch generic GEMM with M=1. Actual one-token input chunks, non-final layers and speculative all-logit plans have different contracts.

| Site | Source of the one prepared row | Destination |
| --- | --- | --- |
| Final query | Quantize FP32 `p.norm` at `(parentRows-1)*hidden*4` via `AddQuantizeQ8_1At`, writing digits/scales at scratch offset zero | `p.q` at offset zero |
| Attention output | Quantize the compact `p.attn` row at its output width | `p.tmp` |
| Gate and up | Share one quantization of the compact post-attention norm | `p.ffnGate` and `p.ffnUp` |
| Down | Use the digits/scales from the existing fused SwiGLU + Q8_1 (or quantize the live FP32 SwiGLU row when required by the existing route) | `p.tmp` |

1. Add a small planner decision at the **prepared product** sites, including the FFN path that calls `AddGemmMmqAt` directly. For an explicitly cropped row whose parent selected MMQ and whose K-quant width meets `AddGemvQ8_1At` requirements, append that existing op with the same weight and prepared buffers. The binding accepts a weight offset and uses zero-based digits, scale and output buffers. Do not reinterpret a nonzero FP32 row offset as an offset into the integer tile. Requantize the selected FP32 row as the current query path does. [Binding](../../../backend/hip/hip.go) · [Matvec kernel](../../../kernels/hip/gemv/gemv_i8.hip)
2. Retain row displacement for final query RoPE/attention, full K/V writes, parent-selected non-MMQ routes and streaming LM head. Non-final chunk submissions skip the marked tail. Test `prefillAllLogits`, parent rows 1/16/127/128, multiple chunks and a short true remainder. Inspect a plan/profile to show **only eligible** cropped products switch, with one quantization for gate/up.
3. Compare the five FP32 outputs on identical quantized input first. Use a CPU integer-dot oracle for the appropriate per-block scales/mins, then run independent same-chunk control/candidate tests at pp128/512/1024/2048. Require finite full logits with max absolute error ≤ 0.05 and matching top-1 and subsequent greedy continuation (at least three steps). Verify K/V and recurrent snapshots against control after a non-final chunk. Run [speculative/all-row regression tests](../../../engine/gpu/prefill_real_test.go) and the real-model suite.
4. Accept when paired, unprofiled whole-prefill measurements reproduce the fixed saving (target 1.0–1.2 ms per final prefill, use ≥ 1.0 ms as the lower gate). Record the fixed final-row component and whole-prompt medians separately. If pulled forward, rerun the paired upstream pp128 gate with the accepted Stage 2 candidate.

Estimate: 25–50 production Go lines, principally in `plan.go`, with differential tests. The prequantized matvec already crosses the ABI.

## 6b — Residual add, RMSNorm and optional quantization

The existing attention/recurrent block and FFN finish with `plan.Add(p.x, p.tmp, ...)`. The next sublayer normally normalizes this updated residual into `p.norm`, then the planner may quantize it for one or more projections. Fuse only when the add and its consuming norm address the same rows, in the same executable portion of the plan.

1. **Add + norm first.** Start with attention/recurrent output → post-attention FFN norm within a layer. In [norm.hip](../../../kernels/hip/ops/norm.hip), add a row kernel computing and writing `x' = float(x + tmp)` in place. Normalize the rounded residual using the 256-thread accumulation order, reduction, epsilon, `rsqrtf` and multiply order of [rmsnorm_batch_f32_kernel](../../../kernels/hip/prefill/prefill.hip). Store FP32 `norm = (x' * invRms) * weight`. Every path needs `x'` for a later residual. Extend to FFN output → next block's attention norm only after checking edge ownership. The initial embedding norm, final output norm, tail mark, compact-row copy and all-row verification impose real boundaries. Leave a separate add/norm when rows, liveness or execution condition differ.
2. **Select outputs per norm group at plan construction.** Derive needed formats from the actual consumers including the cropped query after K/V and the selected Stage 2 gate pair. FP32-only groups use the first op. All-MMQ groups can store only `x'` and `xQ8/xDS` if *every* later consumer accepts those prepared rows. Mixed groups store `x'`, FP32 `p.norm` **and** digits/scales. In particular, for a cropped final layer, materialize FP32 norm if 6a will requantize the last row after the tail mark. Short streaming/WMMA paths and 2a read FP32. Adapt `prefillProjections` and the explicit FFN gate/up branch to consume already-prepared input once. End that scratch lifetime before the SwiGLU/down producer overwrites it.
3. **Add the quantized epilogue.** Form the same rounded FP32 norm values even when the FP32 destination is omitted. Follow [quantize_q8_1_kernel](../../../kernels/hip/gemm/mmq_gemm.hip) for groups of 32, four values per lane, max-abs, `rintf`, clamping, zero-block treatment and `float2(d,d*sum(q))`. Preserve the existing quantizer's order and handle only supported aligned widths. Reuse the per-block quantization code where it preserves that order.
4. **Wire and validate two additive opcodes.** Append `ADD_RMSNORM_BATCH` and `ADD_RMSNORM_QUANT_Q8_1` in the [ABI](../../../backend/hip/bridge/yuuka_hip.h). Document buffer slots e.g. residual in/out, addend, weight, optional norm, digits, scales. Document rows, width/strides, offsets, epsilon and which outputs each opcode requires. Add launch declarations in the [kernel header](../../../kernels/hip/yuuka_kernels.h), validation and execution in the [bridge](../../../backend/hip/bridge/bridge.cpp), typed methods in the [Go binding](../../../backend/hip/hip.go) and [profile names](../../../backend/hip/opinfo.go). Check overflow-safe spans, natural/vector alignment and exact-fit offsets. Permit the intended in-place residual only. Reject overlapping live input/output ranges and append nothing on failure.

**Verification by iteration.** Extend [plan validation](../../../tests/hip/plan_validation_test.cpp) with null/optional norm, short/misaligned buffers, alias and valid disjoint offsets in one buffer. Differential native tests must compare residual and FP32 norm **bitwise**, plus every quantized digit and both FP32 scale/sum fields bitwise to `ADD → RMSNORM_BATCH → QUANT_Q8_1`. Exercise mixed/all-MMQ/FP32-only modes, zero rows of *values*, row tails, cancellation-prone residuals and quantization rounding boundaries. Inspect real plans to verify output liveness and removed launches. Run same-chunk pp128/512/2048 plus a nonaligned multi-chunk prompt and speculative all-row verification against the unfused control. Require identical finite logits and greedy continuations for 6b alone.

**Performance gate.** Interleave 6a-only control and 6a+6b on the verified gfx1151 GGUF, F16 KV, chunk 512, concurrency one, 2 warmups and 5 reps per arm, then reverse process order. Require a repeatable ≥ 2.0 ms unprofiled pp512 saving (3.0 ms target). Verify preserved short, tail and long-prompt medians within measured noise. Record the trace of eliminated add/norm/quant ops and timings separately. Publish per-iteration results with the [project verification commands](../../testing.md#94-current-test-commands).

Estimate for 6b: 180–300 production lines across kernel, ABI/bridge, bindings and planner, plus native and model tests.
